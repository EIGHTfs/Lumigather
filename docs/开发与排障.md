# 开发与排障

改完代码后的自检顺序，以及遇到常见现象时的处理办法。命令都在项目根执行。

## 一、改完代码的自检

**1. 语法检查（后端全部模块）**

```bash
for f in server/app.js server/lib/*.js server/lib/rule/*.js server/routes/*.js; do
  node --check "$f" || echo "FAIL $f"
done
```

没有 `FAIL` 行即通过。

**2. 单元测试**

```bash
for f in test/*.test.cjs; do node "$f" || echo "FAIL $f"; done
```

每个文件末尾应为 `# fail 0`；出现 `FAIL` 行先修再继续。

**3. 重启并看状态**

```bash
./start.sh restart
./start.sh status
```

`status` 会打印进程、PID、监听端口、`GET /api/status` 的返回码与耗时、日志尾；四项都正常才算启动成功。

**4. 端点回归**

```bash
for ep in /api/status /api/directories /api/images /api/lumigather /api/favorites /api/uploaded /api/auto-update/status; do
  printf '%-28s %s\n' "$ep" "$(curl -s -o /dev/null -w '%{http_code}' "http://<NAS-IP>:<端口>$ep")"
done
```

全部返回 `200`。

**5. 用局域网地址再验一遍**

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://<NAS-IP>:<端口>/
```

用真实局域网地址访问，不要用本机回环地址自查——回环能通不代表别的设备能通。

**6. 登录回归**

设置了访问密码后：未登录的写操作返回 `401`，登录后返回 `200`（会话 cookie 名为 `session`）。

**7. 收尾**

- 改过前端（`server/public/` 下的 JS / CSS / HTML）要升 `server/public/index.html` 里的 `?v=` 版本号（当前 48）。
- 测试脚本动过 `server/config.json`（例如目录的分类被改写）就改回去。
- 停掉测试期间起的临时进程再交付。

## 二、常见现象与处理

| 现象 | 处理 |
| --- | --- |
| 局域网其他设备打开页面空白、接口全失败 | 页面与接口必须同端口同源访问；前端接口地址一律用相对路径 `/api/...`，不要写主机名、端口或本机回环地址 |
| 某个接口返回 404 | 路径要带完整 `/api` 前缀；媒体直链走 `/api/media`、`/api/zip/img`、`/api/zip/gif`、`/api/gif`，不要自己拼 |
| 压缩包内的图不显示 | 确认 `7z` 已被探测到；包内没有图片时整组隐藏属正常 |
| 压缩包被显示成一个独立标题 / 分组 | 包内图片应并入同名文件夹分组、不显示压缩包标题；压缩包条目不要当普通图片处理（图片列表跳过，媒体接口对压缩包返回 403） |
| 压缩包内中文文件名乱码 | `zip` 条目名先按 UTF-8 严格解码，失败回退 GBK；`rar` / `7z` 里名字丢字节时换新版 7-Zip 后重扫 |
| `rar` 内图片列表为空、日志报 `Unsupported Method` | 旧版 7-Zip 解不了 `rar` 的新压缩方式，换新版 7-Zip 后重启并重新扫描 |
| 压缩包内中文名变成 `?` 或纯数字 | 旧版 7-Zip 在输出层丢字节，换新版后重扫该压缩包 |
| 侧边栏深层目录不显示 / 点一次后整棵树收起 | 检查每层子目录项是否都带根路径标记；深层目录要按祖先链逐层展开，不能只在路径与当前目录完全相等时才展开 |
| 已展开的目录点了不折叠 | 规则是「已展开点击=折叠不导航，未展开点击=展开并进入」；折叠状态存在浏览器本地 |
| 新增分类后目录下拉里没有它 | 分类增删、改名、改色后重新渲染目录下拉；删除分类时引用它的目录回退到「全部」 |
| 图片行卡片宽度为 0、图片看不见 | 横向排列的图片用流式宽度（高度定值、宽度自适应），不要绝对定位 |
| 改了前端，浏览器还是旧脚本 / 旧样式 | 升 `?v=` 版本号；核对时看服务端返回的文件内容，不要只看磁盘文件 |
| 自动化脚本点按钮无反应 | 分类与目录的添加已改为内联输入框与目录选择器，不再弹系统输入框，脚本直接操作对应控件 |
| 登录后刷新又变回游客 | 页面与接口必须同端口同源；换端口或换访问地址后需要重新登录 |
| 收藏的图片重启后裂开 | 收藏只存相对地址（`/api/media?file=...`），不存带主机与端口的完整地址；旧数据重新收藏一次 |
| 保存设置后页面没变化 | `server/config.json` 每次请求实时读，刷新页面即可；改的是 `.env` 则要重启服务 |
| 访问目录返回 403 `blocked-by-blacklist` | 命中浏览黑名单，调整 `LUMIGATHER_BLACKLIST_DIRS` 后重启 |
| 目录里的图片没有合成 GIF | 目录内图片只平铺显示，合成只针对压缩包；规则见 [压缩包与GIF规则](压缩包与GIF规则.md) |
| 分组显示和预期不一致 | 有子文件夹就分组（默认折叠，点名称进入、点 ▲/▼ 折叠），没有子文件夹才平铺图片 |
| 上传到收藏分类被拒 | 收藏分类不允许上传；未登录只能传到「游客」分类，登录后可选真实目录 |
| 接口返回里没有密码哈希 | 正常，读取配置的接口会剥离密码相关字段 |
