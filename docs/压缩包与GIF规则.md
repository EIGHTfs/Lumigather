# 压缩包与 GIF 规则

## 压缩包直出

不解压即可显示压缩包内的图片，支持 zip / 7z / rar。读取依赖 `7z`，启动时自动探测，
未安装时压缩包相关功能不可用，普通目录浏览不受影响。

```bash
# 列出某目录下的压缩包及其内图片
curl 'http://<NAS-IP>:<端口>/api/zip/scan?dir=/path/to/dir'

# 取压缩包内某一张图
curl 'http://<NAS-IP>:<端口>/api/zip/img?path=/path/to/a.zip&file=images/01.png'
```

## 什么时候翻转

部分贴图在压缩包内是倒置存储的，显示前需要旋转 180°。判定依据是压缩包内的 ini：

| 情况 | 结果 |
| --- | --- |
| 压缩包内没有 ini | 不翻转 |
| ini 里没有 `filename =` 声明 | 不翻转（音频元数据类 ini 属于此类） |
| 该图片的文件名出现在 ini 的 `filename =` 声明里 | 翻转 |
| 其余图片（如预览图） | 不翻转 |

匹配只看文件名、不区分大小写、忽略目录层级。翻转结果缓存，重复访问不再重复转码。

## 什么时候合成 GIF

两组条件任一满足即合成：

| 规则 | 条件 |
| --- | --- |
| 序列帧 | 包内有 ≥3 张编号连续的图片，且包名带帧间隔（如 `@40ms`、`2s`） |
| 带 ini 的序列帧 | 包内有 ≥3 张编号连续的图片，且 ini 里写了 `$speed` |

帧间隔来源按优先级取：请求参数 `dur_ms` → 包名里的间隔 → ini 的 `$speed` 换算。
目录内的图片永不合成 GIF，只按图片显示。

```bash
# 压缩包内序列帧合成（dur_ms 可空，空则按包名或 ini 推算）
curl 'http://<NAS-IP>:<端口>/api/zip/gif?path=/path/to/a.zip'

# 目录内序列帧合成
curl 'http://<NAS-IP>:<端口>/api/gif?dir=/path/to/dir'
```

合成结果缓存于 `cache-gifs/`，可直接删除；删除后下次访问重新合成。
