# 目录与索引机制

## 索引是什么

每个分类一份目录索引，记录「这个目录里有哪些文件、哪些子目录、目录修改时间」。
有了它，列某个分类的图片不必每次重扫磁盘。

```
cache-index/<分类>/index.jsonl
```

一行一个目录，首行是文件头。可直接删除，下次访问按需重建。

## 什么时候建

**只在实际访问时按需建**，不做全量预建：

- 第一次访问某个分类 → 扫目录并写索引
- 之后再访问 → 读索引，只对「目录修改时间变了」的目录重新扫

索引文件可以随时删除：删掉只是让下一次访问变慢，不会丢任何用户数据。

## 索引怎么失效

以目录的修改时间为准。目录内容变了，修改时间随之变化，该目录的索引条目即失效并重扫。
因此「新建/删除/改名文件」都会在下次访问时正确反映。

## 内存缓存

索引文件读入内存后常驻，按「文件修改时间 + 文件大小」判断是否仍然有效；
写入索引后立即让对应缓存失效，避免读到旧内容。

| 项 | 说明 |
| --- | --- |
| 上限 | 默认 128 MB，超出后淘汰最久未使用的分类 |
| 调整上限 | 环境变量 `LUMIGATHER_INDEX_CACHE_MB` |
| 关闭缓存 | 环境变量 `LUMIGATHER_INDEX_CACHE=0` |
| 查看命中率 | `GET /api/index-cache` |

## 分页

`GET /api/images` 支持可选分页，不传时返回全量：

```bash
curl 'http://<NAS-IP>:<端口>/api/images?root=/path/to/lumigather&recursive=true&limit=200&offset=0'
```

| 字段 | 含义 |
| --- | --- |
| `count` | 匹配到的总数（不随分页变化） |
| `total` | 同上，语义化别名 |
| `returned` | 本页实际返回的数量 |
| `limit` / `offset` | 回显本次请求的分页参数；`limit=0` 表示未分页 |
