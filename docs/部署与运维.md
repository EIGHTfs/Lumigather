# 部署与运维

部署前要准备什么、日常怎么启停与改配置、搬家时核对哪些东西，以及遇到问题怎么处理。
命令都在项目根执行，路径都相对项目根。

## 一、部署前提

| 项 | 要求 |
| --- | --- |
| 运行时 | Node.js 18 或更高（`node -v` 自查） |
| 依赖 | 零第三方依赖，不需要安装依赖 |
| 外部工具 | `ffmpeg`（GIF 合成）、`7z`（压缩包读取）；启动时自动探测，缺失只影响对应功能 |
| 网络 | 局域网内设备能访问本机端口；服务监听全部网卡 |

外部工具怎么放：

- 放进项目 `tool/` 目录（`tools/` 同样识别），启动后自动探测。
- 或装进系统 `PATH`。
- 或用环境变量直接指定可执行文件路径：`FFMPEG`、`7ZZ`（`7z` 也认 `SEVEN_ZIP`）。
- 压缩包要读 `rar` 的新压缩方式，需较新的 7-Zip；旧版会报 `Unsupported Method`。

## 二、首次部署

1. 把代码放到目标目录，作为项目根。
2. 确认端口：`server/config.schema.json` 里的 `port.default`（默认 8081）；临时换端口用 `./start.sh --port <端口>`。
3. 启动并检查：`./start.sh start`，然后 `./start.sh status`。
4. 浏览器访问 `http://<NAS-IP>:<端口>/`。
5. 进设置页添加图片根目录与分类；需要限制改设置时先设置访问密码。
6. 需要自动更新时，在设置页打开开关并设置模式与间隔。

## 三、日常操作

| 操作 | 命令 / 入口 |
| --- | --- |
| 启动 | `./start.sh start` |
| 停止 | `./start.sh stop` |
| 重启 | `./start.sh restart`（默认命令） |
| 查看状态 | `./start.sh status` |
| 换端口 | `./start.sh --port <端口>` |
| 设置或修改访问密码 | `./start.sh --set-password "新密码"` |
| 前台调试 | `node server/boot.cjs` |

启停行为：

- PID 写到项目根的 `<项目名>.pid`。
- 日志写 `server/server.log`，超过 10 MB 自动轮转为 `server.log.<时间戳>`。
- 启动后要等健康检查（`/api/status`）通过才算成功；失败会打印日志尾。
- 停止先发 SIGTERM，等待超时仍未退出才强制结束。
- `status` 输出四项：进程与 PID、监听端口、`GET /api/status` 的返回码与耗时、日志尾。

## 四、配置与数据文件

| 文件 / 目录 | 内容 | 改动后 |
| --- | --- | --- |
| `server/config.json` | 分类、目录、标题、密码、自动更新 | 实时读取，无需重启 |
| `.env` | 每行图片数量、浏览黑名单、浏览根等运行参数 | 重启服务后生效 |
| `cache-index/` | 目录索引缓存 | 可删，按需重建 |
| `cache-gifs/` | 合成 GIF 与翻转结果缓存 | 可删，按需重建 |
| `uploads/` | 游客上传的图片 | 不要删 |
| `server/sessions.json` | 登录会话 | 可删，需重新登录 |
| `server/favorites.json` | 收藏 | 不要删 |

常用运行参数（`.env`）：

| 变量 | 作用 |
| --- | --- |
| `LUMIGATHER_IMAGES_PER_ROW` | 每行图片数量，默认 20 |
| `LUMIGATHER_BLACKLIST_DIRS` | 浏览黑名单，命中即返回 403 |
| `LUMIGATHER_FS_ROOT` / `LUMIGATHER_FS_ROOTS` | 只允许浏览的根；不配置即自由浏览 + 黑名单模式 |

环境变量以 `LUMIGATHER_` 前缀为准；旧前缀 `GALLERY_` 仍作回退兼容（新名没设置时读旧名）。

浏览权限默认语义：任意路径都能浏览，只有命中黑名单的路径被拒，比对前会解析真实路径（软链指向黑名单同样被拒）。`server/config.json` 里的目录是快捷入口与分类标签，不是权限边界。

## 五、迁移与备份核对

- 整个项目目录一起搬；`server/config.json`、`uploads/`、`server/favorites.json`、`server/sessions.json` 必须带上。
- `cache-index/`、`cache-gifs/` 可以不带，首次访问会自动重建。
- 外部工具（`ffmpeg`、`7z`）体积大、不入库，需要在新机器单独放置。
- 新机器 Node 版本对得上（18 以上）。
- 启动后逐项点一遍：目录浏览、压缩包内图、GIF 合成、上传、登录。

版本库入库范围（部署端自动更新以仓库为源）：

- 必须入库：`server/core/`、`server/route/`、`server/http/`、`server/auth/`、`server/config/`、`server/store/`、`server/update/`、`server/assemble/`、`server/boot.cjs`、`server/lib/cjs-bootstrap.cjs`。
- 不入库（运行态）：`server/config.json`、`server/sessions.json`、`server/favorites.json`、`cache-gifs/`、`cache-index/`、`uploads/`、`tools/`、`*.log`、`*.pid`、lock 文件。
- 漏入库的框架文件会让部署端永远拿不到新版；框架文件由组装脚本下发，不要手改。

## 六、常见现象与处理

| 现象 | 处理 |
| --- | --- |
| 启动报端口被占用 | `./start.sh status` 看占用情况；或换端口 `./start.sh --port <端口>` |
| 启动后马上退出 | 看 `server/server.log` 末尾报错；`./start.sh status` 也会打印日志尾 |
| 本机能开、局域网打不开 | 用 `http://<NAS-IP>:<端口>/` 访问；确认防火墙没有阻断该端口 |
| 改了 `.env` 不生效 | 重启服务（`.env` 每个进程只读一次） |
| 改了 `server/config.json` 不生效 | 刷新页面；该文件每次请求实时读 |
| 访问目录返回 403 | 命中浏览黑名单，调整 `LUMIGATHER_BLACKLIST_DIRS` 后重启 |
| 压缩包内图全空白 | 没探测到 `7z`，放进 `tool/` 或加进 `PATH` 后重启 |
| GIF 合成失败 | 没探测到 `ffmpeg`，同上 |
| 合成或翻转结果一直是旧的 | 删掉 `cache-gifs/` 下对应文件（或整个目录），下次访问重建 |
| 页面还是旧脚本 | 升 `?v=` 版本号后重新部署 |
| 自动更新没拉到新版 | 查 `GET /api/auto-update/status` 的最近更新时间；确认改动已提交进仓库 |
| 收藏图片裂开 | 收藏只存相对地址；旧数据里带主机端口的地址重新收藏一次 |

## 七、已知限制与待办

| 项 | 说明 |
| --- | --- |
| 手机窄屏 | 布局保持现状，不做响应式折行；横向滑动只作用于图片行 |
| 目录内图片 | 只平铺显示，不合成 GIF；合成只针对压缩包 |
| 上传 | 未登录只能上传到「游客」分类（落 `uploads/`）；登录后可上传到真实目录 |
| 压缩包索引 | 由本程序自行扫描目录与压缩包，不依赖外部索引文件 |
| 大目录首次访问 | 首次访问要扫描并建索引，耗时随图片数量增长；之后走索引 |
| 待办：前端拆分 | `server/public/app.js` 仍是单文件，目录树、图片网格、压缩包分组、灯箱、设置集中在一个渲染函数里，改一处容易影响别处；计划按功能拆成多个文件后重新接入维护性检查 |

安全提示：`.env`、`server/config.json`、`server/sessions.json` 不要提交到公开仓库。
