# 索引内存缓存：命中率、上限与开关

## 解决什么问题

每次请求都从磁盘重读整份目录索引：大分类的索引可达 94 MB / 2 万余行，同一份数据被反复读盘并解析，热态仍要 1.5 秒级。
现在索引整份读入进程内存，重复请求直接命中，不再扫盘。

## 怎么工作

- 第一次访问某分类：从 `cache-index/<分类>/index.jsonl` 读出整份索引并登记到进程内存。
- 之后的请求命中内存，不再读盘。
- 失效判定：索引文件的修改时间或大小任一变化，即视为失效并重新读取。
- 写入索引后立即失效对应缓存，下一次请求读到新内容。
- 上限按索引文件字节数计算，默认 128 MB；超限时淘汰最久未使用的分类（至少保留一份）。
- 只存在于进程内存，不落盘；进程重启后首次访问重新读盘一次。

## 可配置项

| 变量 | 取值 | 默认 | 作用 |
| --- | --- | --- | --- |
| `GALLERY_INDEX_CACHE` | `0` 或 `false` 关闭，其它值开启 | 开启 | 关闭后全部走原读盘路径，用于对照与排障 |
| `GALLERY_INDEX_CACHE_MB` | 正整数（MB） | 128 | 缓存驻留上限，超出淘汰最久未使用的分类 |

两个变量都在服务进程启动时读取，改完需要重启。设置方式：

```bash
# 启动前导出，再照常用启停脚本重启
GALLERY_INDEX_CACHE_MB=64 ./start.sh restart
```

注意：写在项目根 `.env` 里对这两个变量不生效，须通过启动环境传入（启动脚本或系统服务环境）。

## 可查接口：`GET /api/index-cache`

免登录，返回计数与占用：

```bash
curl -s 'http://<NAS-IP>:<端口>/api/index-cache'
```

```json
{"ok":true,"enabled":true,"hit":2,"miss":1,"hitRate":66.7,"stale":0,"evict":0,
 "invalidate":0,"entries":1,"bytes":97889922,"limitBytes":134217728}
```

| 字段 | 含义 |
| --- | --- |
| `enabled` | 缓存是否开启；`false` 表示用 `GALLERY_INDEX_CACHE=0` 关闭了 |
| `hit` / `miss` | 命中 / 未命中的访问次数 |
| `hitRate` | 命中率（百分数，一位小数） |
| `stale` | 命中过旧条目（指纹变化）的次数，已计入 `miss` |
| `invalidate` | 写入索引后主动失效的次数 |
| `evict` | 因超上限被淘汰的分类次数 |
| `entries` / `bytes` | 当前驻留的分类数量与总字节 |
| `limitBytes` | 上限字节数 |

判断：`bytes` 长期贴近 `limitBytes` 且 `evict` 增长，说明上限偏小，可调大上限或减少同时访问的分类。

## 效果参考

索引就绪后：2 万行 / 94 MB 索引的分类约 0.9 秒，较小的分类 0.02–0.3 秒；约 7 万张图的分类为亚秒级。
服务重启后的首次访问要整份读盘：常见 0.5–2.8 秒，系统刚启动、页缓存为空时会到 10 秒级。带 `limit=200` 的分页请求把响应体从约 44 MB 降到约 105 KB。

内存：开启后进程常驻约 600 MB（缓存上限 128 MB，其余为堆与响应体瞬时占用）。设 `GALLERY_INDEX_CACHE_MB=64` 更省，设 `GALLERY_INDEX_CACHE=0` 完全不驻留。

## 已知限制

- 上限是软上限：单个索引超过上限时仍保留一份，驻留字节会高于设定的 MB 数。
- 开启缓存后，读一个目录条目也要先整份载入该分类索引；条目很少、索引很大时首次反而多读，换来后续命中。
- 缓存不跨进程：多实例部署或重启后各自重新读盘。
- 缓存只省索引读取，不省后续构造成本：7 万条的分类响应体约 44 MB，服务端遍历与序列化仍要 0.45 秒量级；分页能减少传输与前端解析，服务端构造仍在。
- 索引文件格式与磁盘布局不变，`cache-index/` 随时可删，删除后按需重建。

## 出问题时怎么判断

1. 命中率一直是 0 → 看 `enabled` 是否 `false`；若 `miss` 一直增长而 `hit` 不涨，检查是否有别的程序在不断改写索引文件。
2. 列表不更新 → 索引文件被原地改写且保留了原修改时间与大小（拷贝工具的保留时间戳选项常见），指纹不变。删除 `cache-index/<分类>/index.jsonl` 或重启服务后重试。
3. 内存偏高 → 看 `bytes` 与 `entries`；调小上限或关闭缓存对比。
4. 想确认缓存不影响结果 → 分别以 `GALLERY_INDEX_CACHE=1` 与 `0` 重启，请求同一地址，比较 `count` 与 `images` 条目数。
