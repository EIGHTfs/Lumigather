# 安卓端界面设计规范

> 用途：Lumigather 安卓端的视觉与布局依据。开工前先读这份，避免边写边拍脑袋。
> 参考来源：`ccch1mneyyy/dsh-Go`（Flutter，AGPL-3.0）。**只取设计令牌与布局思路，不复制其实现代码** —— 一是协议不允许，二是技术栈不同（Dart/Flutter vs Kotlin/Kuikly），实现层本来就得重写。

## 一、设计令牌

数值取自参考项目 `app/lib/ui/theme/` 下的配色与常量定义，不是目测。

### 1.1 配色

**背景（浅色，名为 mist 雾）** —— 冷调浅蓝灰，用于衬托内容：

| 名称 | 色值 | 用途 |
|---|---|---|
| mistTop | `#EBF1FE` | 页面顶部渐变起点 |
| mistBottom | `#F6F7FC` | 页面底部渐变终点 |
| mist | `#F0F4FD` | 基准背景 |
| mistLowest | `#FBFCFF` | 最浅，卡片底 |
| mistLow | `#F6F9FE` | 次级底 |
| mistContainer | `#EEF1F9` | 容器底（搜索框、未选中胶囊） |
| mistHigh | `#E7EBF4` | 高一级容器 |
| mistHighest | `#DFE4EE` | 最高一级容器 |

**文字（名为 ink 墨）** —— 四级层次，不要自己加第五级：

| 名称 | 色值 | 用途 |
|---|---|---|
| ink | `#1E232E` | 主文字、标题 |
| inkMuted | `#4F5562` | 次要文字 |
| inkFaint | `#646974` | 辅助说明 |
| inkGhost | `#A1A5AC` | 占位符、禁用态 |

**分隔与阴影**：

| 名称 | 色值 |
|---|---|
| outlineLight | `#7E838D` |
| ruleLight | `#DCE0E8` |
| shadowInk | `#0B152D` |

**主色（accent）**：种子色 `#4B67B4`（蓝紫）。由种子色派生 pressed / container / onContainer / bubble / glow 各档，暗色主题另有一套 Dark 变体。

**暗色主题（名为 night 夜）**：`#1D222C`（顶）/ `#1B1C23`（底）/ `#1C1F28`（基准）。

### 1.2 圆角

| 值 | 用途 |
|---|---|
| 全圆（99 / 999） | 胶囊按钮、筛选 chip、圆形图标按钮 |
| 20 | 大卡片、底部浮动栏 |
| 16–18 | 列表项选中态、图片卡片 |
| 10 | 小控件 |
| 8 | 小标签 |

### 1.3 间距

严格 8pt grid，实测出现频次：`8`（最多）→ `12` → `16` → `24` → `10` → `6`。

约定：组件内边距 8，组件间距 12，区块间距 16–24。

### 1.4 字号

| 字号 | 用途 |
|---|---|
| 15 | 正文基准（最高频） |
| 13 | 次要文字 |
| 12 | 辅助说明 |
| 11 | 极小注释 |
| 16–18 | 列表项标题
| 20+ | 页面大标题 |

### 1.5 形态规则

- **不用边框和分割线**，靠背景色块与间距分层
- 大面积圆角，所有可点区域都是圆角矩形或圆形
- 图标统一线性风格（细描边），不用实心填充
- 留白充足，列表项垂直内边距 16–18，保证手指点击舒适

## 二、页面骨架

### 2.1 目录页（首页）

```
┌─────────────────────────────────────┐
│ [≡]  ┌──────────────────┐  [👤] [✎] │  ← 顶栏：左圆形按钮｜中间胶囊（标题+状态副标题）｜右两圆形按钮
│      │ Lumigather       │           │
│      │ ● 已连接 · NAS   │           │
│      └──────────────────┘           │
│                                     │
│  ┌───────────────────────────────┐  │
│  │ 🔍  搜索目录或文件             │  │  ← 全宽大圆角搜索框，mistContainer 底
│  └───────────────────────────────┘  │
│                                     │
│  全部目录 ⌄                    ···  │  ← 列表头：标题+下拉｜右侧更多
│                                     │
│  ( 全部 )( 游戏 )( 图片 )( 未读 )   │  ← 筛选胶囊：选中=深色实心，未选中=浅灰底

│  ┌───────────────────────────────┐  │

│  │                             ● │  │
│  └───────────────────────────────┘  │
│  壁纸图库                           │  ← 未选中：纯文字，无背景
│  表情包                             │
│                                     │
│  文件夹                              │
│  📁 工作区                     7 ⌄  │  ← 可折叠分组：图标+名称+计数+箭头
│      明日方舟资源          📌       │  ← 子项缩进
│      主实例验收            📌       │
│                                     │
├─────────────────────────────────────┤
│ [💻] NAS 服务器            (⋯) (⚙) │  ← 底部固定栏：左=连接信息+状态点｜右=工具按钮

```

**与 Lumigather 数据的对应**：

| 界面元素 | 数据来源 |
|---|---|
| 胶囊标题副标题 | `GET /api/lumigather` 的 title + 连接状态 |
| 筛选胶囊 | `/api/lumigather` 返回的 `categories` |
| 目录列表 | `GET /api/directories` 的 `items` |
| 文件夹计数 | 由子目录数量得出 |
| 底部栏状态 | 客户端自己维护（baseUrl + 最近一次请求的延迟/成败） |

│  │    │ │    │ │    │               │
│  └────┘ └────┘ └────┘               │

## 三、组件映射（Kuikly 侧怎么实现）

| 参考项目概念 | 我们的用途 | Kuikly 实现要点 |
|---|---|---|
| 胶囊（pill）按钮 | 筛选 chip、主操作 | 圆角 = 高度/2，用 Box + borderRadius 全圆 |
| 圆形图标按钮 | 顶栏次级操作 | 固定尺寸（如 40×40）+ 全圆 + mistLowest 底 |
| 分组标题 | 「置顶」「文件夹」这类分隔 | 11–13px、inkGhost、无背景、上下留 16 |
| 分段控件 | 信息/操作切换 | 选中态白底圆角浮起，未选中透明 |
| 三列统计 | 图片元信息 | 三等分 Column：大数字（20+）+ 小标签（11–12） |
| 图标+标签+值 | 元信息行 | Row：图标 20 + 标签 15 + Spacer + 值 15（inkMuted） |
| 底部固定栏 | 服务器连接状态 | 固定在页面底部，左信息右工具，与内容区滚动隔离 |
| 列表选中态 | 当前目录 | 淡蓝紫底（accent container 低透明度）+ 右侧 6px 圆点 |

## 四、构建时要守住的几条

1. **只用上面列出的色值**，需要新色先回这份文档加，不要就地写死
2. **间距只用 8 / 12 / 16 / 24**，不要出现 7、13、18 这类
3. **圆角只用 8 / 10 / 16 / 20 / 全圆**
4. **字号只用 11 / 12 / 13 / 15 / 18 / 22**
5. 不用边框和分割线，靠色块与间距分层
6. 每个可点区域不小于 44×44（触屏最小点击区）

## 五、真实数据核实结果（推翻了部分设计）

连真实部署实例（SA6400:8081）实测，结果如下，**首屏设计需按此调整**。

### 5.1 categories 不是空的，而是 8 个游戏分类，每个带专属色

```
崩坏3     #c084fc(紫)    原神      #4ade80(绿)
星穹铁道   #f472b6(粉)    绝区零    #60a5fa(蓝)
鸣潮      #fbbf24(黄)    终末地    #fb923c(橙)
尘白禁区   #38bdf8(天蓝)   赛马娘    #34d399(青绿)
```

`directories` 里每条是 `{path, category}` 的映射，例如：

```
崩坏3   → <存储根>/Game.Patch N MOD/[miHoYo]/Honkai Impact 3 – 崩坏3
原神    → <存储根>/Game.Patch N MOD/[miHoYo]/Genshin Impact – 原神/Mods/.Mods/(gamebanana)
```

**结论：首屏应该是「8 个分类」的入口，不是文件树浏览。** 用户的心智是「我要看哪个游戏的图」，不是「我要在一棵目录树里走」。文件树降为次级页面（点分类进不去想要的图时才用）。

这比参考项目的筛选胶囊更占优势 —— **我们的分类自带颜色**，可以直接做成彩色分类卡，视觉辨识度远高于单调胶囊。

### 5.2 `images[]` 的实际字段

```json
{
  "name":     "loading-logo.f0c3ebe.png",
  "path":     "<存储根>/.../loading-logo.f0c3ebe.png",
  "url":      "/api/media?file=%2Fvolume6%2F...",
  "size":     "已格式化的字符串（如 2.4 MB）",
  "modified": "ISO 时间字符串"
}
```

两点要注意：

1. **`url` 是相对路径**，不是完整 URL。客户端必须自己拼 `baseUrl + url`（对应 3.6 节的前缀处理）。这是最容易漏的一点 —— 直接拿 url 去请求会失败。
2. **没有图片宽高**。详情页的「1920 × 1080」拿不到，除非客户端自己解码后取，或后端补字段。MVP 阶段建议先在详情页省掉尺寸显示，只显示 size 与 modified。

### 5.3 `directories` 与 `images` 的响应里还有额外字段

目录列表实际返回：

```json
{"root": "...", "items": ["Mods", "{Android}"], "limit": "...", "clamped": false, "canUp": true}
```

- `items` 是**字符串数组**（只有名字，不是对象）
- `canUp` 决定是否显示「返回上级」按钮
- `clamped` 表示路径被限制在允许范围内
