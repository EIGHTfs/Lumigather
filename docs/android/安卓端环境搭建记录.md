## 二、从零搭建步骤

### 2.1 目录与权限

编译必须在**本地盘**，不能放 SMB/CIFS 挂载：

- Gradle 需要频繁 `chmod` 与大量小文件写入，CIFS 上报 `Operation not permitted`
- 更致命的是 CIFS 上**二进制文件无法执行**（`aapt2`、`d8`、`adb` 全部 `Permission denied`，即使 `ls` 显示 `-rwxrwxrwx`）

共享文件夹若权限为 `d---------+`（属主 root、仅靠 ACL），需在 DSM 控制面板给对应套件用户授权，**不要用 chmod** —— 对带 synoacl 的共享文件夹根执行 chmod 会清空整棵 ACL。

### 2.2 安装 JDK 17

Kuikly 要求 JDK 17。系统默认 java 若是更高版本（如 25），不要改系统默认，单独装一份：

```
cd <编译根>
curl -L -o jdk17.tar.gz \
  https://mirrors.tuna.tsinghua.edu.cn/Adoptium/17/jdk/x64/linux/OpenJDK17U-jdk_x64_linux_hotspot_17.0.21_9.tar.gz
tar -xzf jdk17.tar.gz && mv jdk-17.0.21+9 jdk-17 && rm -f jdk17.tar.gz
<编译根>/jdk-17/bin/java -version   # 应输出 17.x
```

走清华镜像的原因：Adoptium 官方 API 会 307 重定向到 GitHub Releases，而本机 GitHub 直连不通。

### 2.3 准备 Android SDK

只复制构建真正需要的，不要带模拟器镜像（system-images 约 12G）：

```
<编译根>/android-sdk/  ← 从已有 SDK 复制以下五项
  build-tools/      （aapt2、d8、apksigner）
  platforms/        （android.jar）
  platform-tools/   （adb）
  cmdline-tools/    （sdkmanager）
  licenses/         （Gradle 自动补装组件时需要）
```

**复制到本地盘后必须验证可执行**，不能只看权限位：

```
<编译根>/android-sdk/build-tools/<版本>/aapt2 version
<编译根>/android-sdk/build-tools/<版本>/d8 --output <输出目录> <某个>.class
<编译根>/android-sdk/platform-tools/adb version
```

`d8 --version` 会报 `Error: Invalid output: .` —— 那是参数用法问题，不是执行失败，要用真实 class 文件测才准。

### 2.5 配置工程（三处，缺一不可）

`<编译根>/KuiklyUI/local.properties`：
```
sdk.dir=<编译根>/android-sdk
```

`<编译根>/KuiklyUI/gradle.properties`：
```
org.gradle.java.home=<编译根>/jdk-17
org.gradle.jvmargs=-Xmx2048m -XX:MaxMetaspaceSize=512m -Dkotlin.daemon.jvm.options="-Xmx1536m"
org.gradle.parallel=false
org.gradle.workers.max=2
kotlin.incremental=false
org.gradle.vfs.watch=false
```

构建时的环境变量：
```
JAVA_HOME=<编译根>/jdk-17
```

### 2.6 补装缺失的 SDK 平台

工程各模块的 compileSdk 不一致（30 / 32 / 34 都有），首次构建会报缺：

```
JAVA_HOME=<编译根>/jdk-17 \
  <编译根>/android-sdk/cmdline-tools/latest/bin/sdkmanager --sdk_root=<编译根>/android-sdk \
  "platforms;android-30" "platforms;android-32"
```

### 2.7 构建

```
cd <编译根>/KuiklyUI
JAVA_HOME=<编译根>/jdk-17 setsid nohup bash gradlew :androidApp:assembleDebug \
  --no-daemon --no-watch-fs > /tmp/build.log 2>&1 < /dev/null &
```

首次构建约 9–10 分钟（293 个 Task）。`--no-daemon` 避免常驻进程占内存；`--no-watch-fs` 绕过下面第 2 条坑。

## 三、四个坑与解法

### 坑 1：`org.gradle.java.home` 管不到启动 Gradle 的 JVM

**现象**：`gradle.properties` 里写了 `org.gradle.java.home=<jdk17>`，但 `bash gradlew --version` 输出 `JVM: 25.0.3`。

**根因**：`org.gradle.java.home` 只决定 **daemon / build JVM**；启动 Gradle 本身的 launcher JVM 由 `JAVA_HOME` 决定。二者是两个不同的 JVM。

**解决**：两个都配 —— `gradle.properties` 写 `org.gradle.java.home`，同时在命令前加 `JAVA_HOME=<jdk17>`。验证标准是 `gradlew --version` 里 `JVM:` 行显示 17.x。

**防再犯**：验证 JDK 是否生效，只看 `gradlew --version` 的 `JVM:` 行，不看 `java -version`（`java` 会被 PATH 带到系统默认版本）。

### 坑 2：CIFS 挂载导致 Gradle 枚举文件系统 NPE

**现象**：构建 4 秒即失败：
```
java.lang.NullPointerException
  at net.rubygrapefruit.platform.internal.FileSystemList.add(FileSystemList.java:31)
  at ...PosixFileSystemFunctions.listFileSystems(Native Method)
  at org.gradle.internal.watch.vfs.impl.DefaultWatchableFileSystemDetector.detectUnsupportedFileSystems
```

**根因**：Gradle 7.x 用 native 库枚举系统挂载表做文件监听，遇到本机的 CIFS 挂载项解析失败，直接抛 NPE。

**解决**：关闭文件系统监听 —— `gradle.properties` 加 `org.gradle.vfs.watch=false`，命令加 `--no-watch-fs`。

**防再犯**：在这类"有特殊挂载"的 NAS 环境里构建 Gradle 工程，先关 vfs watch 再尝试。

### 坑 3：`nohup` 起的构建会被会话清理杀掉

**现象**：`nohup bash gradlew ... &` 启动后，父 shell 退出时代码进程消失，日志停在中间无结尾，也没有 BUILD FAILED。

**根因**：`nohup` 只忽略 `SIGHUP`，而进程仍属于原会话的进程组，会被会话清理一并终止。

**解决**：用 `setsid` 让进程完全脱离会话：
```
setsid nohup bash gradlew ... > log 2>&1 < /dev/null &
```

**防再犯**：长时构建一律 `setsid nohup`；判断是否真跑起来了用 `ps aux | grep java`（Gradle 的进程名是 `java`，不是 `gradle`，用 `pgrep gradle` 会误判为没启动）。

### 坑 4：默认 JVM 参数超出本机内存

**现象**：工程默认 `org.gradle.jvmargs=-Xmx5120M -Dkotlin.daemon.jvm.options="-Xmx5120M"`，两个 5G 合计 10G，而本机总内存 8G、可用仅约 4.3G。

**根因**：Kuikly 官方按开发机（通常 16G+）配置，未考虑低配构建机。

**解决**：下调为 Gradle `-Xmx2048m` + `MaxMetaspaceSize=512m`、Kotlin daemon `-Xmx1536m`，并关并行（`org.gradle.parallel=false`）、`workers.max=2`、`kotlin.incremental=false`。

**防再犯**：改 `gradle.properties` 前先看 `free -m` 的 `available` 值，按可用内存分配，不要照抄官方默认。

## 四、验收标准

构建成功的判据不是「没有报错」，而是这四条同时成立：

1. 日志出现 `BUILD SUCCESSFUL`
2. APK 文件存在且体积合理（当前 27M）
3. `aapt2 dump badging <apk>` 能完整解析出 package / minSdkVersion / launchable-activity
4. `apksigner verify --print-certs <apk>` 显示 V2 签名有效

本机实测结果：
```
package: com.tencent.kuikly.android.demo  versionName 1.0
minSdkVersion 24 / targetSdkVersion 32 / compileSdkVersion 34
launchable-activity: com.tencent.kuikly.android.demo.KuiklyRenderActivity
签名: V2 Signer, CN=Android Debug
```
