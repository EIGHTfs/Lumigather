# 索引与性能实现记录

记录索引读路径的性能优化：问题定位、实现方案、实测数据、踩过的坑与未做的部分。
面向需要维护或继续优化这块代码的人。

## 一、问题与定位

### 改前表现

`GET /api/images?recursive=true` 在部署环境的实测（热态，同一份数据连续三次取中位）：

| 分类 | 索引文件 | 首次访问 | 热态 |
| --- | --- | --- | --- |
| 原神 | 94 MB / 21237 行 | 9.74 s | 1.65 s |
| 星穹铁道 | 34 MB / 7525 行 | 2.65 s | 0.44 s |
| 绝区零 | 32 MB / 7618 行 | 2.26 s | 0.51 s |
| 鸣潮 | 32 MB / 5560 行 | 2.18 s | 0.53 s |
| 崩坏3 | 2.1 MB / 1657 行 | 0.77 s | 0.22 s |
| 终末地 | 1.3 MB / 542 行 | 0.34 s | 0.07 s |

热态仍需 1.65 s，说明瓶颈不在磁盘冷读，而在每次请求都重复做同一件事。

### 根因

索引读路径有两个入口，此前都直接读盘，没有任何进程内缓存：

| 函数 | 调用方 | 行为 |
| --- | --- | --- |
| `readDirEntryJsonl(category, key)` | `getDirEntry` | 打开文件、1MB 缓冲流式扫描、命中即停 |
| `loadAllJsonl(category)` | `walkWithIndex` | 流式解析整份文件为 `Map` |

同一个分类的索引被每个请求重新打开、重新解析。成本与索引体积线性相关，
所以「索引越大越慢」——而索引体积又随目录数增长，形成正反馈。

## 二、方案：按指纹失效的内存 LRU

新增 `server/lib/index-cache.js`，把「读盘结果」按文件缓存，用文件指纹判断是否仍然有效。

### 失效键为什么必须是 mtime + size

只用 `mtime` 不够：同一毫秒内多次改写时 `mtime` 可能不变，会读到旧内容。
带上 `size` 能覆盖「行数变化」这类最常见的索引写入。

```js
function fingerprint(file) {
  const st = fs.statSync(file);
  return { mtimeMs: st.mtimeMs, size: st.size };
}
```

命中判定要求两个值都相等；任一不同即视为失效并回源。

### 容量与淘汰

按文件字节数估算占用，超限后淘汰最久未使用的条目。`Map` 的插入序即 LRU 顺序：
命中时先 `delete` 再 `set` 把它移到队尾。

| 项 | 值 |
| --- | --- |
| 默认上限 | 128 MB |
| 调整 | `GALLERY_INDEX_CACHE_MB` |
| 关闭 | `GALLERY_INDEX_CACHE=0`（回退到原读盘实现） |
| 最少保留 | 1 条（避免超大文件永远无法缓存） |

### 写路径必须主动失效

指纹只是兜底。写路径在 `renameSync` 完成后立即调用 `invalidate(file)`：

```js
fs.renameSync(tmp, file);
indexCache.invalidate(file);   // 落盘后立刻失效，不依赖指纹
```

涉及两处：`upsertDirEntryJsonl`、`writeAllJsonl`。

### 配置读取时机

环境变量**用时读取**，不在模块加载时读快照：

```js
let explicitEnabled = null;      // null = 未显式设置，跟随环境变量
function currentEnabled() {
  return explicitEnabled === null ? envEnabled() : explicitEnabled;
}
```

原因见第五节第 2 条。

## 四、分页：只解决了传输层

### 做法

`GET /api/images` 增加可选 `limit` / `offset`，不传时返回全量（零行为变化）。
响应新增 `total` / `returned`，`count` 保持「总数」语义不变。

参数解析与切片抽成纯函数 `server/lib/paginate.js`，便于单测覆盖边界：

```js
resolvePaging(query)          // 缺失/非数字/≤0 ⇒ 0（表示不限）
slicePage(list, paging)       // 不传时原样返回入参（零拷贝）
```

### 实测

原神分类（72258 条）热态：

| 请求 | 耗时 | 响应体 |
| --- | --- | --- |
| 不带 limit | 1.018 s | 44,076,354 字节 |
| `limit=200` | 0.451 s | 107,568 字节 |
| `limit=200&offset=200` | 0.452 s | 106,760 字节 |

正确性：第 1 页 == 全量[0:200]、第 2 页 == 全量[200:400]，逐条一致。

### 为什么服务端只快了 2.3× 而不是预估的 8–15×

成本分解（同规模 72258 条、8.8 MB 响应体的合成数据）：

| 环节 | 8.8 MB 实测 | 折算 44 MB |
| --- | --- | --- |
| 服务端 `JSON.stringify` | 99 ms | ≈ 495 ms |
| 前端 `JSON.parse` | 115 ms | ≈ 575 ms |

分页消除了序列化那 495 ms，但**切片发生在逐条构造之后**：
遍历、`formatSize()`、`toISOString()` 的成本与「返回多少条」无关。
所以剩下的 0.45 s 是构造侧固定成本。

**结论**：分页/裁剪类优化要看清「切片发生在构造前还是构造后」。
发生在后，收益上限就只有序列化 + 传输那一段。

## 五、踩过的坑

### 1. fd 泄漏 + CIFS 上 rename 失败（同一个根因）

现象：索引改写报 `EACCES: rename '.index.jsonl.<pid>.tmp' -> 'index.jsonl'`，
且遍历大目录树后进程 fd 耗尽。

根因：

```js
try {
  let inFd = null;                    // ← 声明在 try 块内
  inFd = fs.openSync(file, "r");
} finally {
  if (typeof inFd !== "undefined")    // ← finally 是另一个块，访问不到
    fs.closeSync(inFd);               //   恒为假 ⇒ 从未关闭
}
```

`let` 是块级作用域。声明在 `try` 内的变量，`finally` 里看不到。

排查中一度误判为「CIFS 不支持 rename 覆盖」，实测澄清：

| 操作 | CIFS 上结果 |
| --- | --- |
| rename → 目标不存在 | ✅ |
| rename → 覆盖已存在文件 | ✅ |
| rename → 目标有未关闭读句柄 | ❌ EACCES |
| copyFile → 覆盖已存在 | ❌ EPERM |
| unlink 后 rename | ✅ |

所以修法是关掉句柄，而不是换写文件的方式（换 copyFile 反而会踩 EPERM 并丢原子性）。

### 2. 环境变量读快照导致配置失效

现象：把 `GALLERY_INDEX_CACHE=0` 写进项目根 `.env`，行为不变。

根因：`.env` 由 `lib/config.js` 的 `loadDotEnvOnce()` **懒加载**注入 `process.env`
（首次调用 `resolveImagesPerRow` 时才执行）；而缓存模块在**加载时**就读了 `process.env` 快照。
两者加载顺序不保证，缓存模块先加载时读到的永远是「未设置」。

修法：改为用时读取（见第二节末），并加回归用例钉住「加载后再设环境变量必须生效」。

### 3. 等价性比对的 key 必须全局唯一

第一版验证脚本用「目录 basename」做 key，而 4 个分类的目录名都是 `(gamebanana)`
⇒ 互相覆盖 ⇒ 误报「哈希变了」，差点据此回滚一个正确的优化。

### 4. 不要用 grep 结果推断功能是否存在

排查 `setup.sh --dry-run` 时，用 `grep "[dry-run]"`（方括号）数出 0 次，
据此判断「功能没实现」并改了代码；实际输出格式是 `(dry-run)`（圆括号），功能一直是好的。
判断功能是否存在，看实际输出，不要只看某个字符串有没有匹配上。

## 七、可复用的检查清单

改动这块代码前后，按下面几项自查：

| 检查项 | 判据 |
| --- | --- |
| 缓存是否可能读到旧内容 | 失效键是否同时包含 mtime 与 size；写路径是否主动 invalidate |
| 配置是否真的生效 | 环境变量是否在用时读取（而非模块加载时快照） |
| 句柄是否释放 | 所有 `openSync` 对应的 `closeSync` 是否在能执行到的块里 |
| 行为是否等价 | 开关式隔离：同代码 + 同数据 + 只切开关，逐字节比 |
| 收益是否真实 | 端到端耗时（不是纯操作耗时），且标注数据规模 |
