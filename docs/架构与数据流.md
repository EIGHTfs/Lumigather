# 架构与数据流

## 一个进程，两种角色

`node server/boot.cjs` 起一个 HTTP 服务，同一个端口既服务页面也服务 API：

```
浏览器 ──┬─→ GET /                 → 静态页面（server/public/）
         └─→ GET /api/images?...   → JSON 数据
```

不需要额外的静态服务器，也不需要数据库。

## 请求怎么走

```
HTTP 请求
  → 鉴权层（设置页需要密码；浏览类只读接口放行）
  → 路由分发（按路径 + 方法）
  → 业务处理
      · 目录类：读目录索引 → 过滤 → 排序 → 返回 JSON
      · 媒体类：读文件/压缩包 → 直接输出字节流
  → 响应
```

## 数据落在哪

| 目录 | 内容 | 可否删除 |
| --- | --- | --- |
| `server/config.json` | 站点配置（分类、目录、密码、自动更新） | 不建议，删除后需重新配置 |
| `cache-index/` | 目录索引缓存 | 可删，会按需重建 |
| `cache-gifs/` | 合成好的 GIF 与翻转后的图片 | 可删，会按需重建 |
| `uploads/` | 上传的图片 | 不可删，是用户内容 |
| `server/sessions.json` | 登录会话 | 可删，删除后需重新登录 |

## 前端

页面是单个 HTML + 若干静态 JS/CSS，无构建步骤：

```
server/public/
  index.html        页面骨架
  app.js            业务脚本（已预拼好的单文件）
  api-client.js     统一的 API 封装
  locales/          中英文案
  fragments/        HTML 片段与样式分片
```

浏览器端按需加载：进入某个目录时先取当前层（快），再补齐其余层级并合并，切换视图时不清空已有内容。

## 端口与访问

服务监听端口在启动时确定，启动日志与设置页都会显示。同一局域网内用 `http://<NAS-IP>:<端口>/` 访问即可，不需要额外开放路径。
